Lines to Pipes

Releasedi-Civil

Any mix of lines, polylines, arcs and feature lines into pipes in one network, set up once

What it does

Lines to Pipes is Civil 3D's Create Pipe Network from Object for many objects at once. Select any mixture of lines, polylines, 3D polylines, arcs and feature lines - pick, window, crossing, or a selection made before the command - then set the network, parts and elevations once, and every pipe is built in one pipe network in one transaction. The dialog has the native fields: network name (the native Network - (<[Next Counter]>) template is filled in; an existing network's name adds to that network - its own parts list is proposed, any other can be chosen, and the network keeps its own parts list setting), description, parts list, pipe to create, structure to create, plan layers, surface, alignment, erase existing entity, use vertex elevations and the vertex elevation reference.

- Geometry is not simplified. One pipe per piece: a line is one straight pipe; an arc, and every arc segment of a polyline or feature line, is a curved pipe on the same circle; a line-arc-line polyline gives straight, curved, straight. A feature line breaks at its PIs, and - with vertex elevations - at its elevation points too, so grade breaks between PIs are kept. Every arc is carried as three points (ends and midpoint), each midpoint checked against the source object with GetClosestPointTo, and handed to Civil 3D's three-point PipeCurveGeometry, whose own reading (GetArc2d) must match before any pipe is made. No bulge-sign convention is assumed. A feature line's GetBulge is not assumed to count its pieces one way: it is read by PI, and - when that does not fit and the line has elevation points - by each PI's place among all its points, then piece by piece across all its points. Only a reading whose every piece, straight or curved, lies on the feature line is used; the log records which one fitted, or the line's raw data. Confirmed in Civil 3D 2026 on 15 feature lines (October 2026): GetBulge counts every point, elevation points included, and the bulge at a PI's place is that of the whole piece after it - so "by PI" only fits a line without elevation points, and the second reading fits the rest. - Pipe sizes come from the part. Inside height, wall and outside height are read from the parts list, converted from the catalogue's units (a millimetre parts list in a metre drawing is normal), and then confirmed against the first pipe Civil 3D builds; if Civil 3D's figures differ, they are used. Nothing is typed in. - Vertex elevation reference turns each vertex elevation into the centreline Civil 3D stores: centreline as is, invert plus the half-bore (or the part's own base-point offset), crown minus it, outside bottom/top with the wall added. With Use vertex elevations off, Civil 3D's pipe and structure rules set the elevations from the surface, as the native command does. - Where pipes meet. Ends that coincide (within 0.001 drawing units - the only tolerance, there to absorb floating-point noise between snapped points) share one junction: one structure, however many pipes arrive. *Structure to create* can be a structure (one at every pipe end, shared), a null structure (only where pipes meet; open ends stay open, as in Civil 3D's pipes-only layout), or <none> (nothing connected). Adding to an existing network, an end inside one of its structures - by Civil 3D's own IsPointInsideStructureRegion - connects to it rather than getting a duplicate. Ends that are close but not together are listed, never joined silently. - Nothing half-made. Everything is checked before the drawing is touched: every object (an object that cannot be converted is named by handle, and blocks the run unless you tick *leave them out*), the settings, every curve against Civil 3D. The write is one transaction; afterwards every pipe is read back and checked - straight or curved, ends, elevations, arc, connections - and any failure rolls the whole run back, network included. Source objects are erased only after all of that, and a failure names the object and segment it came from.

The rules are LinesToPipesPlanner, FeatureLineSegmenter, PlanArcs and PipeSection in Core, unit-tested; the drawing side is iCIVIL.Importers\LinesToPipes. Every run's numbers - sections, curve construction, each pipe as built - are written to the log.

How to open it

Click Lines to Pipes on the i-CIVIL ribbon tab, or type ICIVILLINESTOPIPES at the command line.
