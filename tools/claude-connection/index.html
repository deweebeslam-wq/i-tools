What it does

i-TOOLS → AI → Claude Connection connects Claude (Claude Code, Claude Desktop or any MCP client) directly to the running Navisworks. Claude can then read the federated model, search and select items, look at the view, work with sets, viewpoints and Clash Detective, run the i-TOOLS engines, and run C# against the full Navisworks API.

Connect once: 1. Start Navisworks. The MCP server starts with it (switch this off in the Connection window). 2. Open i-TOOLS → Claude Connection and press Copy command, then run it in a terminal: claude mcp add --scope user itools-navis -- "%LOCALAPPDATA%\i-TOOLS\Navisworks\Mcp\bridge\I-TOOLS.Navis.Mcp.exe". For Claude Desktop, press Add to Claude Desktop (other servers are kept; a .bak is written). 3. Press Test connection. The bridge is copied to %LOCALAPPDATA%\i-TOOLS\Navisworks\Mcp\bridge on start, so the path stays valid after updates and needs no admin rights.

Permissions. Every tool declares what it needs. The default profile, Assisted Editing, lets Claude read, select and move the camera freely. Every change to the document (sets, viewpoints, clash edits, colours saved with the file, file operations, i-TOOLS engines, C#) opens an Allow / Deny dialog in Navisworks. The dialog shows the call, its arguments, the code for C# calls, and can show the named items first. Other profiles: *Read Only*, *Trusted Automation* (changes run without asking; deleting, file operations and C# still ask) and *Custom* (per permission). Files are only written or read inside the allowed folders (default Documents\i-TOOLS MCP).

Items are addressed by itemId ("<model>:<path>", returned by every listing) or by Revit Element ID. Lengths are millimetres. Large results are paged.

Speed (hospital sample, 43k geometry items, Navisworks 2024): a warm call takes about 2 ms; finding 1,467 walls by property 1.2 s; an image 1–1.5 s; a few Element IDs about 50 ms each. C# is compiled outside Navisworks by the bridge (about 2 s), so the compiler never loads into Navisworks and the UI does not freeze while it runs.

Security. The pipe accepts only the Windows user who runs Navisworks, with a fresh token per server start. AI-written C# runs with full access, so it is always asked unless you change that permission.

tools\iTools.Mcp.Tests drives it through the real bridge (iTools.Mcp.Tests <bridge exe> <out> [pid], or … call <tool> <json|@file> for one call).

Features

  • Group - Tools
  • Document - navis_document_info, navis_list_models, navis_open_file (open / append), navis_refresh_models, navis_save_file
  • Model & properties - navis_tree, navis_find_items (property conditions, AND/OR, per model, in selection), navis_get_properties, navis_property_table, navis_property_catalog, navis_category_counts, navis_set_properties (user-defined tab, default i-TOOLS; merges, null removes)
  • Selection - navis_get_selection, navis_set_selection, navis_select_by_element_id
  • View - navis_view_image (the view as an image Claude can see), navis_get_camera, navis_set_camera (position/target, iso/top/front/right), navis_zoom_to, navis_visibility (hide / isolate / show all), navis_section_box, navis_color_override, navis_reset_appearance
  • Sets & viewpoints - navis_list_sets, navis_create_set (search or selection, folders), navis_list_viewpoints, navis_apply_viewpoint, navis_save_viewpoint, navis_rename_saved_item, navis_delete_saved_item
  • Clash Detective - navis_list_clash_tests, navis_get_clash_results (paged, by status/group, grid location + level), navis_show_clash_result, navis_run_clash_tests, navis_update_clash_results (status, assignee, comment; named results or a whole group), navis_group_clash_results (by level, grid, model, category, type, element, status, assignee; dry run; ungroup), navis_create_clash_test
  • i-TOOLS - itools_clash_report (PDF/HTML), itools_property_export (CSV/XLSX/JSON + audit), itools_open_tool
  • Diagnostics - navis_connection_status, navis_list_instances, navis_use_instance, navis_get_execution_log
