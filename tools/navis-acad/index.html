Navis > Acad

Releasedi-Civil

Import 3D blocks from the active Navisworks selection at exact XYZ coordinates (in Navisworks: right-click > Send to Civil 3D)

What it does

Two halves. In Navisworks Manage / Simulate 2025, select items, right-click and choose Send to Civil 3D (or Send Measured Points to Civil 3D after a point-to-point measure). In Civil 3D, click Navis > Acad (ICIVILNAVIS2CAD). One block per item lands at its exact world coordinates.

Why it is quick. Navisworks writes one binary file, %LOCALAPPDATA%\iCIVIL\NavisCoordBridge\latest_export.bin, and Civil 3D reads it in its own process. Navisworks never drives AutoCAD over COM, so a selection of thousands of triangles builds in seconds, not one remote call per face. Identical vertices are stored once, and triangles with no area are dropped.

Exact coordinates. Doubles are written bit for bit. Each block holds its mesh about the item's bounding-box centre and is inserted at that centre: WCS, scale 1, rotation 0, normal +Z. Adding the centre back to the local vertices reproduces the world coordinate bit for bit (tested at UTM coordinates). Navisworks itself stores mesh vertices as single-precision floats with double-precision transforms. Nothing is lost on top of that.

What counts as one item. It follows what was picked. A file, layer or plain group expands to the objects in it. An object (geometry, a composite object, a block insert) is one block with all its visible geometry merged. Hidden items are skipped. Items with only lines or points are reported: there is nothing to mesh.

Sending again replaces. An item imported before, matched by source file + handle (else instance GUID, else tree path), has its old inserts erased and its block redefined. There are never duplicates. The whole import is one transaction and one UNDO. Esc cancels it with nothing left behind.

Units. Navisworks' document units are compared with the drawing's INSUNITS, and the coordinates are scaled to match. Feet against US survey feet is deliberately 1:1: Navisworks has no survey foot, so the numbers are already the drawing's, and scaling by the 2 ppm difference would move a state-plane coordinate by feet. An unset INSUNITS means no scaling, with a note. On the Navisworks side, each item's extracted triangles are also checked against the bounding box Navisworks itself reports. A difference that is exactly a unit ratio is corrected; anything else is logged.

Messages. A send more than a day old is asked about before it is imported. An empty or missing buffer, one being written, and a damaged one are each reported. The Navisworks side logs every send (counts, time, corrections) to navisworks.log beside the buffer.

The exchange format, units, mesh welding/splitting, block names and XData layout are in iCIVIL.Core\Coordination, unit-tested. That includes a file written by the .NET Framework 4.8 build and read by the .NET 8 build. The Navisworks plugin is iCIVIL.Navisworks (net48, built against Navisworks 2025). It compiles those same Core sources, so there is one definition of the format.

How to open it

Click Navis > Acad on the i-CIVIL ribbon tab, or type ICIVILNAVIS2CAD at the command line.
